# Online coloring

The site remains static HTML, vanilla JavaScript and locally compiled Tailwind. `#color-online` opens the studio; `#coloring` still opens paper printables. Existing routes, homepage collections, metadata, CSP and hosting assumptions are preserved. No backend or new production dependency is needed.

## Library and provenance

The studio has **51 choices: 50 pictures and Blank page**, all available in Draw. **20 pictures support Color**: ball, apple, star, banana, pear and 15 original vectors. Thirty detailed raster pictures support Draw only. The [complete artwork inventory](coloring-inventory.md) reviews all 35 existing PNGs, their 35 WebP previews and 210 localized PDFs. PDFs repeat the same artwork with localized print furniture; they are not additional motifs. Existing provenance follows README's documented printable pipeline; this review makes no new external ownership claims.

The newly authored collection is birthday cake, balloons, cupcake, rainbow, ice cream, flower, butterfly, house, little car, kite, teddy bear, smiling sun, moon and stars, dinosaur and rocket. Source SVGs are in `assets/coloring/svg/`. These original paths were authored for this repository in November 2026, without external generation, third-party assets or copied characters. JSON definitions record their provenance.

`assets/coloring-library.js` is generated by `python tools/prepare_studio.py` from existing `PRINTS` names, `tools/studio-catalog.json` and the authored SVG collection. Each entry has:

```js

  labels: {en: 'Birthday cake', de: 'Geburtstagskuchen', /* all six locales */},
```

Blank page uses the engine's built-in definition and requires no fetch. Original printable IDs containing underscores map once to hyphenated studio IDs. Keep approved IDs stable when editing filenames or ordering.

The gallery stays visible below the workspace. Blank page is pinned. All, Animals, Food & treats, Toys & play, Nature, Party and Bailabu filter a bounded scrolling grid. Buttons have native keyboard activation, pressed states, visible focus and a selected check mark. Category strips scroll within their own bounds on narrow screens. Thumbnail images use native lazy loading; larger artwork definitions load only when selected and are cached in memory.

## Definition and SVG authoring contract

`assets/coloring/{id}.json` contains intrinsic dimensions, stable region IDs, path data, six-digit default colors and provenance. Approved raster pictures contain a data-PNG ink layer over fills. Draw-only raster definitions have zero regions and explicit `modes: {color:false, draw:true}`. Color requires nonempty validated regions. The engine and UI enforce capabilities. Color is disabled with a localized explanation for Draw-only pictures; choosing one automatically uses Draw. Returning to a Color-capable picture restores the requested mode.

Author new pictures as inspectable SVG files with `viewBox="0 0 800 1000"` and a stable `data-picture-id`. Use groups `background`, `regions`, `decoration`, and optionally `underlay` for lines behind paint regions. Every paintable path needs a unique semantic ID such as `icing`, `left-wheel` or `flame`, a closed path and generous touch regions. Supplied motifs use thick 12-unit outlines, white defaults, rounded joins and no text. Paint outlines share region geometry; decoration and underlay have no paint identity and use `pointer-events="none"`. Runtime paint regions target fill geometry, so nonpaintable lines never intercept taps. Preserve viewBox and aspect ratio. Layer order controls occlusion, never identity.

Only numeric SVG M/L/H/V/C/A/Q/S/T/Z path commands are accepted. No scripts, handlers, CSS URLs, images, fonts, external references or arbitrary SVG markup. The preparation script rejects unapproved elements and attributes and checks IDs and closure, then compiles authored paths into the narrow JSON contract (`vector`, `regions`, `underlay`, `decoration`). Production code constructs SVG elements without inserting markup. The engine rejects duplicate, empty, malformed and remotely referenced definitions; the UI offers retry or another picture. No SVG optimization is disabled. The page build does not rewrite these assets; `test-studio.js` compares source IDs against production definitions.

To add a motif:

1. Author a consistent original SVG with large closed regions; inspect it at phone size.
2. Add six explicit labels and a category in `tools/studio-catalog.json`.
3. Run `python tools/prepare_studio.py`, then the focused checks below.
4. Review the source contact sheet, rendered stage and exported PNG. Preserve IDs when revising geometry.

Original ball/apple/star preparation remains in `tools/prepare_coloring.py` (Pillow/OpenCV). Do not rerun casually: these approved definitions remain byte-for-byte unchanged by the expansion script. `prepare_studio.py` uses the established offline contour method only for the two individually reviewed fruits; it checks their four-region counts and assigns stable semantic IDs. A source change needs visual review even if the count stays the same. Character pictures are deliberately not fed through automatic fill detection. Small fruit stem/leaf areas are a higher-complexity option alongside the much larger simple motifs. Raster ink is deterministically downsampled to 800 × 1000 maximum; original printables remain intact. No preparation occurs on a child's device.

## State and bounds

`coloring-engine.js` owns immutable per-artwork session state. `coloring-ui.js` handles Pointer Events and SVG/controls; `coloring-renderer.js` replays strokes for screen/export; `coloring-export.js` composes PNG. Canvas pixels and DOM attributes are projections, never canonical state.

Each state retains picture ID, dimensions, capabilities, current/default fills, ordered strokes, past/future content history, mode, tool, color and size. Strokes retain tool, six-digit color, intrinsic width (8/20/40) and ordered finite points within artwork bounds. Inputs are validated and copied. Tool settings do not consume history. Each picture, including Blank, retains independent work. Clearing one never clears another. Language, route, responsive and orientation changes preserve completed actions; reload/closing discards them.

Undo/Redo restores one completed fill, drawing, eraser or reset action. A new action clears Redo. History structurally shares fill/stroke references, never serialized SVGs or PNGs. Per picture: 80 undo/redo entries, 160 current strokes including erasers, 1024 points per stroke. Dense active paths halve interior samples while retaining endpoints. At most about 240 distinct strokes can be retained per picture through history. Across all sessions, a further limit of **800 distinct strokes and 300,000 points**, counting unique stroke objects in current/past/future snapshots, prevents the larger library multiplying worst-case memory. Additions over the budget are rejected with the existing localized save/undo/reset message; no older work is silently evicted. All 51 sessions are finite; artwork definitions total approximately 4.8 MB on disk and load on selection.

Brush uses round connected paths. Crayon is a translucent path plus five deterministic dashed wax ridges, with no randomness or texture request. Eraser uses `destination-out` on the transparent drawing layer only; base ink, fills and background remain protected and erasing is independently undoable. Pressure is not required.

## Blank page and responsive coordinates

All current definitions use intrinsic **800 × 1000** coordinates. Blank is white, has no regions/ink, supports Draw only and uses the same state/export path. Its `.blank-stage` fills the entire inner frame width and a responsive `clamp(280px,64dvh,760px)` height. It does not inherit the centered portrait template's maximum width. The surrounding frame contains only deliberate 8px padding and a 3px border; neither is presented as artwork.

Pointer positions derive from the actual Canvas rectangle and independently map x/y into stable intrinsic coordinates. The blank workspace can change aspect ratio with layout: canonical content stretches with that rectangle, keeping the same normalized edge/corner positions; PNG remains the intrinsic portrait aspect. This deliberate tradeoff uses the full available stage without cropping or inventing invisible margins. Shapes can therefore look proportionally different between a wide blank workspace and its portrait export. All four corners, all four edges and center are covered by pixel/coordinate tests before and after rotation. Templates preserve their source aspect ratio.

A ResizeObserver, window/visual-viewport resize and DPR-change listeners replay from canonical data. Backing resolution uses CSS size × DPR clamped to 1–2, with a 2400-pixel cap per dimension. Every replay resets transforms. RequestAnimationFrame batches active segments; there is no polling or perpetual render loop. Crayon preview overlaps can settle on canonical replay.

Pointer down/move/up use one path for mouse, pen and touch, primary-pointer checks, capture and optional coalesced samples. One gesture commits at most one stroke. Cancel/lost capture discards only the unfinished preview. Leaving bounds ends the stroke, preventing re-entry lines. Secondary pointers/nonprimary buttons are ignored. Mode/tool/picture/language changes, page hiding and blur cancel unfinished gestures. Only the active Draw surface uses `touch-action:none`; normal page scrolling and browser zoom remain elsewhere. Pinches starting on the surface are reserved for drawing.

## Export and print

PNG export clones only the base SVG, strips focus/interaction attributes, rasterizes background + fills + ink/vector art, then composites a separate transparent replay of strokes after eraser effects. Output is always **1200 × 1500**, independent of CSS viewport and DPR. Blank exports the complete intrinsic area. Thumbnails, selected frames and controls are excluded. Tests check every curated color and blank edges. Raster ink is embedded and authored vectors are same-origin, keeping export origin-clean.

The safe `toBlob` path uses a temporary Blob URL and `bailabu-{picture}.png`. SVG source URLs are revoked in `finally`; download URLs after 60 seconds for browser handoff. Concurrent exports are disabled. Missing Canvas/Blob APIs, image/serialization failures and null PNG blobs show the localized fallback. Successful dispatch cannot prove the user saved the file.

Print on paper retains the original `#coloring` collection and localized PDF preview/download flow for all 35 existing printable motifs. It prints the original page, not the completed studio drawing. It is hidden for Blank and new SVG motifs, which have no established paper-print path. Completed pictures can be saved as PNG and printed using the device's own image tools; no new print window is introduced.

## Accessibility, localization and privacy

Modes, tools, sizes, colors, templates and category buttons expose pressed states. Undo/Redo/reset expose disabled states; Color is disabled when unsupported with a localized explanation. Native buttons/links remain keyboard reachable with visible focus, without traps or hover dependence. Fill regions provide a non-freehand artistic path via Enter/Space. Freehand drawing requires pointing input; there is no simulated keyboard drawing. Reduced motion, browser zoom and silent operation remain supported.

All six locales (EN/DE/ES/PT/TR/AR, including RTL) cover template labels, categories, color names, Blank and capability explanation. New translations live in `tools/studio-catalog.json`; existing tool/mode words remain in `coloring-ui.js`. Proper character names follow the existing localized printable catalog. Artwork contains no text. Adding a palette entry, template or control requires all six accessible labels and responsive checks.

Studio data stays in memory. No persistence, account, upload, telemetry, cookies, sharing, backend, remote artwork or new production dependency is added. Existing site language/game preferences, aggregate GoatCounter counting and parent contact form remain unchanged; studio controls carry no counting events. This is not a site-wide no-tracking claim. CSP and static hash routing remain unchanged.

## Focused validation

After changing `index.html`, run `bash tools/build_page.sh` using **Git Bash** on Windows (`C:/Program Files/Git/bin/bash.exe`). It runs the existing video-cache audit, Edge English prerender and Tailwind compilation. Video-catalog warnings are independent of the studio. There is no package manifest, lint command or type checker.

```sh
python tools/prepare_studio.py
node tools/test-coloring.js
node tools/test-studio.js
bash tools/build_page.sh
python -m http.server 8765 --bind 127.0.0.1
# In another terminal, while the preview runs:
python tools/check_coloring_browser.py
python tools/check_drawing_input.py
python tools/check_studio_browser.py --screenshots
python tools/check_games_browser.py --flows-only
```

Maintenance-only Pillow/OpenCV are used for preparation; Python Playwright controls installed Edge. No browser package/dependency is shipped. `prepare_studio.py --review` optionally writes the original artwork contact sheet to OS temp. `preview-studio.html` provides the new SVG contact sheet and colored fruit conversion review. Screenshot outputs stay in OS temp.

Logic checks cover malformed/duplicate definitions, IDs surviving production, all source-art coverage, capabilities, exact colors and aggregate history bounds. Existing browser checks cover collections/print dialog, keyboard fills, tools/sizes, mixed history/branching, recoverable reset, per-picture work, cancellation/lost capture/secondary input, dense samples, resize, export failure/concurrency, reduced motion and six locales. Native input checks cover trusted Edge mouse/pen/emulated touch, capture/cancel, keyboard and DPR 2.

Expansion checks open/draw on all 51 choices, fill all 20 capable pictures, export representative old/new/vector/raster/Blank assets, test all 18 exact PNG colors, and verify blank corners/edges/center and replay/export at 320 × 568, 390 × 844, 768 × 1024, 1024 × 768 and 1440 × 900. They also check touch targets, capability/print visibility, keyboard template switching, isolated reset, categories, six-locale labels and RTL overflow. Optional screenshots include all 15 motifs, both prepared fruits and all five layout classes.

These are automated structural/pixel/input checks plus targeted visual inspection, not a formal accessibility audit or physical-device study. Real iPadOS/Safari, Android WebView, hardware touch/stylus, screen readers, OS palm rejection and device download behavior remain unverified. Browser download restrictions may use preview/save UI. Cloudflare deployment is outside this workflow.
